# 개찰결과 실제 공개 감지

입찰공고 알림을 실제 발송한 공고만 번호·정규화 차수로 추적한다. 개찰예정시각과 입찰마감시각은 발송·제외·조회 대기의 근거로 사용하지 않는다. 나라장터 공개 응답이 동일 번호·차수의 개찰완료·유찰·재입찰임을 확인하고 직접 링크를 검증한 뒤 기존 ntfy 채널에 최초 1회 알린다. 최종 낙찰자 확정은 추적하지 않는다.

이미 발송한 결과와 과거에 실제 공개를 확인하여 제외한 결과는 기존 SQLite 상태를 유지한다. 전환 시 확인한 과거 공개 18건은 core/opening_baseline.json에 명시적 번호·차수 목록으로 남긴다. 예정시각에서 과거 여부를 추정하지 않는다. 전환 전 성공 조회에서 결과가 없었던 공고가 이후 공개되면 예정시각과 무관하게 알린다.

기존 공고 알림을 먼저 처리하고 약 2분 호출과 실행 직렬화를 유지한다. 공공데이터 API 추가 사용량은 0건이다. 나라장터 공개 화면에서 기존 검색어 4종의 최근 7일 결과를 실행당 4회 조회하고 추적 중인 공고만 대조해 우선 확인한다. 100건 초과나 검색어·기간 누락 건도 번호별 순환 조회로 확인한다. 발송 전 번호별 조회와 직접 링크 검증을 거친다. 실행당 번호별 조회는 최대 8건, 동시 최대 4건이다. 모든 공고를 날짜와 무관하게 순환 확인한다. 이전 날짜 기준으로 잡힌 대기시각은 최초 1회 초기화한다.

조회·전송 실패는 다음 실행에서 재시도한다. 확인 결과를 먼저 DB에 저장하고 ntfy 성공 후 발송 완료를 기록한다. ntfy 수신 이력의 고유 개찰키로 응답 유실·DB push 실패 후 중복을 억제한다. 이력 조회 실패 시 발송을 연기한다. 처리 25초가 지난 실행은 추가 발송을 시작하지 않고 확인 결과를 저장한다. Actions 대기·조회 한도·장애에 따라 발송이 늦어질 수 있다.

DB는 기존 persist_state.py nara가 충돌 확인 후 저장하고 취소·실패 시 복구 artifact를 보관한다. ntfy와 Git은 하나의 원자적 거래가 아니므로 DB와 수신 보관 이력이 모두 유실되면 절대적인 exactly-once는 보장할 수 없다.

검증: python -m unittest discover -s tests -v. 기존 알림 회귀, 과거·미래·미상 날짜의 실제 공개 결과, 과거 공개 재발송 방지, 신규 공개 우선 처리, 조회 실패 시 순환 조회, 전송 재시도, 수신 이력 복구, DB 충돌을 확인한다. 나라장터 PBOC006_01 실제 응답과 PBOC007_01 원본 화면의 입력 인수 및 직접 링크 연결을 검증했다.
